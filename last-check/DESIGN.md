# Design System — CH01–CH10 and endings

## Use context

「마지막 확인」은 한국어 선택형 추리 웹게임이다. 기존 구조에 배경7·초상6·제목1·자료컷4·엔딩컷4를 적용한다. 한이경을 유지하고 새 초상은 현장 대사 공개 후만 표시하며 녹음/문 너머/참고컷에는 세우지 않는다. 자료컷은 공개 완료 후, 엔딩컷은 확정 경로의 마지막 묘사 블록에만 contain으로 표시한다. BAD01 암전은 그림을 제거한다. 정확한 문서·서명·시각/버튼은 HTML이다. 미수신 문서3·GOOD 가족사진 부재·기존 잔색이 남으므로 전체 미술 완료와는 별개다.

## Direction

야간 기록원에서 보전용 사건 기록을 읽는 인상. 어두운 주변 화면 위에 밝은 기록지를 놓고, 미술보다 원문과 선택의 위계를 우선한다. 그라디언트·유리 효과·장식 아이콘·완성 미술을 가장하는 처리를 사용하지 않는다.

## Tokens

`src/ui/app.css`의 루트 토큰을 단일 기준으로 사용한다.

- `--night`, `--night-raised`: 주변 화면과 미수신·실패 그림 영역
- `--paper`, `--paper-deep`: 대사 기록지와 장면 메타데이터 띠
- `--ink`, `--ink-soft`: 본문과 보조 정보
- `--rule`: 기록지 구분선
- `--accent`, `--accent-hover`: 진행·선택 상태
- `--focus`: 키보드 포커스

본문 기본 서체는 sans-serif 계열, 원문 블록과 수첩 본문은 `ui-serif` 계열이다. 본문 너비는 `.story-block`의 `72ch`를 넘기지 않는다.

## Surface hierarchy

`.play-stage` 안의 순서는 고정한다.

1. `.stage-art`: 상단 장면 그림. 기존 배경은 `cover`, 추가 배경 5종과 인물은 `contain`으로 소품·얼굴·손·단추를 보존한다. 설명 참고컷은 인물 없이 HTML 설명 띠로 구분하며 장소이동을 뜻하지 않는다. 미수신·실패는 중립 배경이며 이전 그림을 유지하지 않는다. 매핑·공개 경계는 `docs/ART_ASSETS.md`를 따른다.
2. `.scene-strip`: 현재 scene ID·제목과 블록 진행 수.
3. `.dialogue-panel`: 현재 원문 블록 한 개.
4. `.choice-state`: 원문 선택 시점에만 대사 아래 표시.

수첩은 `.notebook-toggle`로 열고 `.notebook` 안에서 전체 기록·증거·진술·인물·시간표·명단·가설판·로그 탭을 전환한다. 획득과 공개 이력을 함께 검사해 실제 읽은 기록만 렌더링하며, 잠긴 증거·개발자 ‘쓸모’ 설명·선택하지 않은 결과 문장·미래 텍스트는 DOM과 접근성 트리에도 만들지 않는다.

## Interaction states

- 게임 시작 전 진행 버튼은 `CH01 시작`이다. 저장 관리와 수첩은 게임 진행과 독립적으로 열 수 있다.
- 타이핑 중: 현재 블록만 표시하며 “현재 문장 모두 표시”로 즉시 완성할 수 있다.
- 표시 완료: “계속”이 순수 전이를 실행한다.
- 선택: 조건 미충족 선택도 비활성 상태와 이유를 표시하며 엔진에서 다시 검사한다.
- 결과: 대응 결과 블록을 모두 표시한 뒤 원문 `next`로 이동한다.
- 종료: 각 엔딩 마지막 카드 뒤 종료 문장을 표시하고 `타이틀로` 화면 명령을 제공한다. 복귀는 이전 실행의 보상을 합산하지 않는 새 실행이다.
- 빈 수첩: 비밀 텍스트 없이 “아직 공개된 기록이 없습니다.”만 표시한다.
- 대조 자료: 읽은 명단·시간표 문서를 고정 표시한다. E07 미보유 관련 세 행은 확정 정보가 아닌 후보로 표시하고 E04 미보유 항목은 정의 미확인으로 표시한다.
- 비밀: CH08 녹음 미보유는 `미청취`, CH10 미획득 개인 증거는 제목·개수·슬롯 없이 숨긴다. 선택 ID·조건 수식·proof/full은 화면에 노출하지 않는다.
- 기본 메뉴·저장 관리는 헤더 버튼으로 여는 대화상자 영역이다. 이어하기(미존재·비호환 시 비활성)·새 게임 시작·타이틀 복귀(진행 중 교체 확인 모달 포함)·자동1/수동3·지목전 보호본·엔딩 원본의 실제 도달 챕터 분기·설정/엔딩 수집을 구분한다. 메뉴가 열린 동안 본문 진행 입력을 차단하고 닫을 때 트리거로 포커스를 복귀한다.
- 저장 상태는 실제 쓰기 확인 후에만 완료로 표시한다. 오류/충돌은 메모리 진행 안내와 재시도·명시적 자동 불러오기·원본/메모리 내보내기를 제공하며, 원본 보관을 확인하지 못하면 복구 덮어쓰기도 하지 않는다.
- 헤더의 `읽기 설정`은 같은 메뉴의 설정 제목으로 바로 이동한다. 대사 크기3단계·속도3단계(9/18/45ms)·즉시표시·모션 줄이기를 제공한다. 크기/속도/사용자 모션은 UI 전용 `last-check.reading.v1`, 기존 즉시표시는 기존 profile 키를 사용하며 게임 저장 스키마는 바꾸지 않는다. 설정 쓰기 실패는 탭 내 적용과 미저장 안내로 구분한다. 음향 구현이 없어 음량/음소거·자동재생을 가장하지 않는다.

게임 효과는 React 렌더·마운트·이미지 로딩에서 실행하지 않는다. 빠른 연속 입력에는 기대 block·scene ID를 포함하고, 이미 지나간 중복 전이는 reducer가 무시해 다음 블록 건너뛰기를 막는다.

## Accessibility

모든 버튼은 44px 이상을 시작 기준으로 하고 3px 키보드 포커스 링을 표시한다. 메뉴/진행 교체 확인창/모바일 수첩은 Tab·Shift+Tab을 내부에 유지하고 배경 입력을 차단하며 Escape/닫기로 트리거에 복귀한다. 수첩 탭은 방향키·Home·End로 조작한다. 현재 원문 전체는 `.sr-only`에 한 번 제공하고 타이핑 glyph는 `aria-hidden`으로 두어 글자별 live 알림을 만들지 않는다. OS 모션 감소의 실시간 변경 또는 사용자 모션 줄이기는 즉시표시·애니메이션 중단으로 적용한다. 첫 입력은 전체표시, 다음 명시 입력만 진행하며 자동진행·강제대기·시간제한은 없다. 반복 Enter/Space와 문서 선택/복사로 블록을 건너뛰지 않는다.

## Responsive rules

- 840px 초과: 수첩이 열리면 플레이 무대 오른쪽에 고정 폭 열로 둔다.
- 840px 이하: 수첩은 별도 스크롤 가능한 dialog로 열고 본문을 inert 처리한다. 닫기 헤더는 수첩 안에서만 sticky이며 종료 후 페이지 스크롤/포커스를 복구한다.
- 620px 이하: 헤더·읽기 설정·저장 작업과 선택은 한 열이다.
- 대사·문서·선택은 자연 높이와 페이지 세로 스크롤을 사용한다. 선택을 고정 높이에 가두지 않는다. 360×800/390×844/1366×768 및 실제 Chrome 200% 확대에서 마지막 항목에 접근한다. 인물 contain과 기존 배경 cover 프레이밍은 유지한다.

## Reuse rule

동일한 `.play-stage`, `.dialogue-panel`, `.choice-list`, `.notebook` 구조를 전 구간에 재사용한다. 원문 연결·자동 검증 완료는 최종 미술·사람 플레이·배포 완료를 뜻하지 않는다.
